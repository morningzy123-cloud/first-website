# 每周报告输出格式

每次在私有运行目录保留以下文件；原始报告不进公开仓库：

- `submission.json`：结构化事实、证据、变更和 28 项覆盖记录。
- `research-report.md`：人可阅读的中文研究结果。
- `query-log.json`：实际检索词、国家/车型/栏目、检索时间、工具、可访问原文与访问失败。不要记录账户/令牌。
- `candidate/run-report.md`：prepare 自动生成的变更与异常概要。
- `candidate/publish.json`：执行发布后自动生成的 PR、提交、部署验证状态；无变化或只演练则无发布记录。

## research-report.md 的内容

开头写研究日期、窗口、模式（真实周更/工具演练）、是否有发布授权、当前状态。再依次写：

1. **本周最重要的变化**：只列有依据的新变化，最多 4 条；一句结论、事实、日期、原始来源。无则明确无可发布变化。
2. **各国/车型变化表**：国家、车型、栏目、原值、新值、可比性、有效期、采用/未采用及理由。无可靠销量保持缺失，不补估算。
3. **来源与证据**：列 sourceId、直接 URL、市场/版本、访问日期、证据定位、冲突处理。正文短引文保持克制。
4. **缺口与失败**：无法访问、来源不一致、旧活动无期限、统计口径不明等；写下一步具体查谁/哪份原文。
5. **覆盖记录**：四国七类的实际状态；KZ海运可不适用。没查到和没查不是一回事。
6. **发布结果**：有变化时给 PR、提交、校验和正式站验证；失败时给已完成阶段和失败原因。没有实质变化就不创建 PR。

## 给用户的最终反馈

控制在一屏，中文：

> 本周已更新上线 / 本周无可发布变化 / 更新未完成（说明停在哪一步）。
>
> 网站：正式链接。更新：最重要的 1–4 项。待核实：必要的 1–3 项。发布：PR与验证结果。研究报告：私有文件位置。

不得把“PR已创建”“CI通过”或“Vercel显示成功”单独当作正式站内容已核对。不得把工具模拟测试写成真实市场研究，也不得暗示未配置的定时任务已经运行。
