# Marketing Buddy｜自动周更与部署说明

## 最简单的使用方式

以后每周把仓库中的 `automation/WEEKLY_UPDATE_PROMPT.md` 连同 `skills/marketing-buddy-weekly-update/` 交给另一个具备网页研究和 GitHub 写入能力的 AI，并为它设置定时任务。它会按四国固定范围检查最近 30 天变化、更新数据、运行校验，并在安全边界内触发网站更新。

## 自动流程

```text
定时启动
  → 读取周更规则和当前线上数据
  → 四国 × 最近30天研究
  → 检查现有活动是否过期
  → 生成候选数据与周报
  → 数据校验 + 四国页面测试
  → 判断是否需要人工审核
      ├─ 不需要：提交 GitHub main → Vercel 自动部署 → 核对线上状态
      └─ 需要：建立审核分支/报告 → 不改变线上版本
```

## 可自动发布的更新

- 官方价格变化；
- 官方促销的开始、变化与到期；
- 官方金融方案；
- 官方保修与售后政策；
- 口径可比的销量更新；
- 有明确日期和来源的官方营销活动；
- 不改变事实含义的来源元数据修正。

## 必须人工审核的更新

- 增加、删除、采纳或调整竞品层级；
- 将国家税则推断为某一辆 EMGRAND 的确定适用税号；
- 权威来源之间存在实质冲突；
- 修改数据结构、网页代码、视觉设计或品牌；
- 修改部署方式或定时计划。

## 失败保护

- 没有变化时只输出“无变化报告”，不创建空提交。
- 任一数据校验或页面测试失败时，线上版本保持不变。
- 不允许强制推送、重置主分支或绕过人工审核边界。
- 发布后必须返回提交 SHA、部署状态和网站地址；无法确认上线成功时不得报告成功。

## 仓库内关键文件

- `automation/weekly-update.config.json`：市场范围、路径、自动/人工边界。
- `automation/WEEKLY_UPDATE_PROMPT.md`：可直接交给定时 AI 的任务文本。
- `skills/marketing-buddy-weekly-update/SKILL.md`：完整周更操作规则。
- `scripts/validate-data.mjs`：生产数据校验。
- `scripts/test-site.mjs`：四国页面回归测试。
