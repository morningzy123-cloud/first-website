# 给外部 Agent 的雷达周更指令

为 Marketing Buddy 执行一次“汽车出口运输与政策风险雷达”更新。先从 `morningzy123-cloud/first-website` 最新 main 读取 `automation/RADAR_UPDATE.md`、`data/radar.json`、`scripts/radar-data.mjs`，完整遵循规则。正式站 https://first-website-five-chi.vercel.app/#/radar 。

覆盖天津出发至沙特、阿联酋、卡塔尔、墨西哥、秘鲁、智利、哈萨克斯坦、乌兹别克斯坦。查最近7天；漏跑时补查自上次成功核查以来的窗口。逐国检查运输/港口、航线/口岸延误、车辆准入/税则三类，共24项覆盖记录。优先核对中东承运限制、红海/霍尔木兹/阿曼湾、实际可执行替代港和陆桥；不泛化其他公司的安排，不把绕海峡视为无风险。

公开资料支持事实；合理推断只进规划估算，并说明依据。时间从实际离津启运开始，至清关放行为主要口径，配送/PDI另外参考。不要生成虚假实时船位、实际ETD、当前口岸排队或准入结论；索引和读取失败只能待核查。政策必须区分现行/拟议、税号、车型、主体及生效日。未登记车型与项目不编造。

保留私有研究报告、覆盖记录、原文定位及差异；先审查再改 `data/radar.json`，运行 `node scripts/radar-data.mjs --build` 及规范中的完整校验。只改雷达JSON与生成bundle，不改UI、Skill、脚本、信任域名、四国竞品数据或范围。不使用原四国 `publish.mjs` 发布此模块。

本任务授权在该固定范围内创建 `radar-weekly/日期` 分支和数据PR，核对对应head SHA的CI及Vercel预览成功后合并，触发既有自动部署，再按merge SHA和正式站两份数据确认发布。权限需在实际定时运行环境可用；缺失时报告，不能声称发布成功。无实质变化不改日期、不提交、不部署。失败或状态不明先查已有PR，不强推、不盲目回滚。

结束返回一屏中文：成功/无变化/未完成；重要变化、运输估算调整及依据、待核查事项、PR、正式链接、生产验证、私有研究报告位置。只在完成、失败或需要处理时通知。该任务独立于原四国竞品周更，可由同一个外部Agent串行运行。
