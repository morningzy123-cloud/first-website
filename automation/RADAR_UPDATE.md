# 出口风险雷达：数据与更新规范

产品入口为 `#/radar`；覆盖 SA、AE、QA、MX、PE、CL、KZ、UZ。起点为天津港；中亚以天津港铁路中心站实际发车为 D0。四国竞品研究与本雷达分别更新，现有 `scripts/weekly/publish.mjs` 仍只接受原三份文件。

## 页面与数据

- 八国总看板：风险摘要、路线示意、启运至清关放行区间、另列配送参考。
- 国家页：两种候选方案、路线节点、阶段估算、假设启运日/上市日/额外缓冲测算、风险结论、受影响目的地车型、旁边可点击依据。
- `data/radar.json` 是本模块唯一数据源；`data/radar.bundle.js` 用 `node scripts/radar-data.mjs --build` 生成。禁止分别手改。
- `radar.js`、`radar.css`、底图与验证脚本属于界面/基础设施；研究更新代理不能修改。

## 时间口径

1. 不计中国起运前的集货、装船/装车等待。用户输入的是假设实际启运日，不是已确认 ETD。
2. 每段 `min/max` 为顺序相加的日历天区间。最后一段固定 `id: local`，单列配送/PDI参考；此前合计至目的地清关放行。某阶段已含边境手续，不重复加整段站到站时效。
3. 当前全部 `basis: estimate`。公开常态班轮表、历史实际航次、历史搜索索引、规划推断必须在 `basisNote` 区分。不得把上海、青岛或乌鲁木齐时效直接标成天津全程。
4. 集装箱 `sea_container`、滚装 `roro`、铁路集装箱 `rail_container` 分开。资料证明走廊存在，不等于确认整车、新能源、装载方式、危险品资质或舱位。
5. 首次认证、扣货、无限期停航或封港不计入区间。海湾常态进湾路线维持 `reference_only`，直到另行开发经审核的实际订舱数据；时间估算不能作为恢复通航证据。
6. 额外缓冲是用户情景输入，不是概率置信区间。PDI就绪不表示已获销售准入。

## 风险与证据

- 来源优先：政府/海关/监管法规正文、港口运营者、承运公告、原始航次资料；新闻只作线索。当前快照不是 AIS、提单或自动安全监测。
- 每个来源留唯一 ID、标题、发布者、精确 URL、可确认的发布日期（未知填 null）、实际核查日、`retrieval`、`supports` 及使用限制。
- `primary` 仅用于直接读取的正文/PDF；索引、摘要、403/418/502 页面记 `reference_only`，不能单独支撑 `confirmed` 风险或新税率。
- `checkedAt` 是确实核查的日期，不能为了周更刷新。每条风险的 `checkedAt` 驱动7天时效；超期自动显示“待复核”，不是继续显示已确认当前状态。`expiresAt` 是公告明确到期日，未知为 null，不编造。
- 风险类别为 `transport` 或 `policy`；等级 `high` / `watch` 是研究分级，不冒充政府安全评级。持续关注不等于已发生延误，无当周证据不展示当前拥堵天数。
- 政策写结论、适用车型/主体/年款、具体税号/原产地与方案、法律状态及生效日。既有基线要求不能伪装成当周新政策；提案、征询结束不等于生效。关税与 VAT 分列，不自动计算综合落地税负。
- 对应国家已有车型只按目的地提示“可能涉及”；不代表已确认受影响。新四国无已登记车型，不编造上市项目。用户排期输入只在本页内存使用，不上传保存。
- 海湾直进波斯湾走霍尔木兹；吉达南向路线才涉及曼德海峡/红海。太平洋拉美航线、中亚陆路不套用红海必经告警。
- 来源冲突保留旧可核验数据、列待核查，不只取更新或更短的天数。未知新域名会被验证器拦截，需要单独审核基础设施改动，不得关闭验证。

## 单次研究交付

保留私有研究底稿：每国检查运输/港口/法规税则三类，共24项覆盖记录（checked_no_change、updated、not_found、blocked），查询窗口、原文定位、短摘录、查证时点、来源冲突、估算推导及与旧版差异。不要将私有底稿、认证文件、项目名、凭据、客户发运数据上传公开仓库。

候选交付仅两文件。执行：

```text
node scripts/radar-data.mjs --build
node --check radar.js
node --test scripts/radar.test.mjs
node scripts/validate-public.mjs
node scripts/test-site.mjs
node --test scripts/weekly/core.test.mjs
```

这些校验能检查格式、范围、分段区间、来源域名与证据等级，不能代替人工/AI对原文事实的审阅。

## 发布与定时运行

本次新增模块不会自动创建定时任务。外部 Agent 需显式保存这份规范及 [雷达周更指令](RADAR_WEEKLY_PROMPT.md)，并具有网页阅读、Node 22+、Git/GitHub及既有仓库权限。

从最新 `main` 读取资料后，使用 `radar-weekly/YYYY-MM-DD` 分支；仅允许修改上述两份雷达数据，创建数据PR。确认该 PR 最新 head SHA 对应的 GitHub 校验及 Vercel 预览成功；复核主分支未变，以预期 head SHA 合并，再确认 merge SHA 的 Vercel 生产部署成功，并比对正式站两份数据字节。网络不明先查已有PR/部署，不重复提交，不强推、不绕过检查。

无事实或估算依据的实质变化时不发布，不改日期。需要代码、车型池、新官方域名、来源权限或架构改动时单独报告，保持已有数据在线。可与原四国周更同一时段运行，但使用独立分支，串行合并避免旧基线。
